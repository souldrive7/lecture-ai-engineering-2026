# 第1回 解答

## 演習

使用モデルは `gemini-3.5-flash-lite`。

「AIE2026の宿題の3レベル」について尋ねたところ、モデルは講座資料を持っていないと断ったうえで、「初級・中級・上級」など複数の一般的な分類を推測した。用語集での正解は「基礎・実装・発展」で、どれか1つに取り組めば完了である。モデルは本講座で使われている正確な名称と条件を特定できず、「Level 2まで必須の場合が多い」など、本講座には当てはまらない例も生成した。

このことから、一般知識については回答できても、講座固有の情報は外部データなしでは信頼できないと気づいた。

トークン表示の実動作例は、LoRA質問で入力7、出力624、合計631。Copilotで `app/ask.py` の `usage_metadata` 表示を実装し、人間が差分を確認した後、実APIと17件のテストで検証した。

## 宿題

- 取り組んだレベル: 発展（実装課題にも取り組んだ）。提出画面の選択は最高レベルの「発展」。

### 実施内容

- `scripts/day1_benchmark.py` を作成した。
- `gemini-3.5-flash-lite` と `gemini-3.8-flash` を比較した。
- LoRAの質問と、講座固有の3レベルについての質問を比較した。
- 各モデル・質問の組み合わせを3回ずつ、合計12回計測した。
- `generate_content` の処理時間を `time.perf_counter` で計測した。
- `usage_metadata` から入力・出力・合計トークン数を取得した。
- リクエスト間隔は15秒、HTTPタイムアウトは120秒、SDKの試行回数は初回を含めて1回（自動再試行なし）とした。
- 1件ごとにCSVへ書き込んで `flush` し、中断後は既存行を保ったまま未記録の組み合わせだけを再開するようにした。
- 結果ファイルは [`lectures/01/benchmark_results.csv`](./benchmark_results.csv)。

### 実装課題: 会話履歴

- `app/ask.py` に `--chat` 対話モードを追加した。
- `client.chats.create(model=MODEL)` で作成した同一チャットセッションを、複数の `send_message` で再利用する。
- 既存の単発質問モードは後方互換で維持した。
- 空入力、`/exit`、`/quit`、EOF、KeyboardInterrupt、APIErrorに対応した。
- 会話内容やAPIキーをファイルへ保存しない。
- fake client / fake chatを使い、外部APIなしで履歴保持、空入力、終了、APIエラー後の継続、トークン表示、非保存をテストした。
- 最終的にpytest 17件が成功した。

実APIでの確認はモデル `gemini-3.5-flash-lite` を使用した。1問目で検証用の架空データである合言葉「青い彗星」を伝え、2問目で合言葉を尋ねたところ、モデルは「青い彗星」と回答した。

| 質問 | トークン表示 |
|---|---|
| 1問目 | input=15, output=27, total=42 |
| 2問目 | input=53, output=16, total=69 |

2問目で入力トークン数が増え、回答内容も合言葉と一致したことから、会話履歴が引き継がれたことを確認した。合言葉は検証用の架空データである。

### 結果

平均時間・中央値・トークン数は成功した計測だけを対象とする。トークン数は成功時の平均値である。

| モデル | 質問 | 成功数 | 成功時平均時間 | 成功時中央値 | 平均出力トークン | 平均合計トークン |
|---|---|---:|---:|---:|---:|---:|
| gemini-3.5-flash-lite | LoRA | 3/3 | 2.939秒 | 2.971秒 | 543.7 | 550.7 |
| gemini-3.5-flash-lite | 3レベル | 3/3 | 4.186秒 | 3.078秒 | 484.7 | 505.7 |
| gemini-3.8-flash | LoRA | 1/3 | 162.078秒 | 162.078秒 | 787 | 1816 |
| gemini-3.8-flash | 3レベル | 0/3 | — | — | — | — |

`gemini-3.8-flash` のLoRA質問は、成功1回のほかはHTTP 503が2回だった。3レベル質問は3回とも約119秒でHTTP 504だった。LoRAの162.078秒の成功記録は、120秒タイムアウトを追加する前の初回実行時の記録である。成功は1件だけなので、この中央値は代表的な性能値とはみなせない。

### 考察

- `gemini-3.5-flash-lite` は6/6成功し、6件の平均時間は3.562秒、中央値は3.024秒だった。
- `gemini-3.8-flash` は6件中1件成功だった。今回の測定時間帯と無料枠環境では、安定性と待ち時間が課題だった。
- リクエストは15秒間隔で実行し、毎分4回以下に抑えた。429は発生していないため、数値上のレート上限超過とは断定しない。
- HTTP 503はService Unavailable、504はGateway Timeoutを示す。今回の記録だけでは、混雑、バックエンド障害、通信経路など具体的な原因を一意に特定できない。
- `gemini-3.8-flash` の成功時の合計トークン数1816は、入力7と出力787の合計を上回る。thinking等の追加使用量が含まれる可能性はあるが、内訳を直接記録していないため断定できない。
- 各条件の測定はn=3かつ単一時間帯のため、この結果をモデル一般の性能差へ一般化しない。

### 問題と改善

初回実行では9/12件まで進んだ後、進行が止まり、プロセス全体が34分を超えたため安全に中断した。原因はSDK内部でのHTTP応答待ちで、当時はタイムアウトが未設定だった。その後、120秒タイムアウトと再試行制限を設定し、CSVを追記して未完了分だけを再開できるようにした。既存の9件を失わず、残り3件を計測し、3件ともHTTP 504として記録した。HTTPエラーの記録も削除せずCSVに残した。

### 再現方法

次のコマンドでテストを実行し、続けてベンチマークを実行する。現在のCSVには12組すべてが記録済みのため、この状態で実行すると全件をスキップし、APIリクエストは送信されない。未記録の組み合わせがある場合だけAPIリクエストを送り、その結果をCSVへ追記する。

```sh
uv run pytest -q
uv run python -m scripts.day1_benchmark
uv run python -m app.ask --chat
```

ベンチマークには `--repeats`、`--delay-seconds`、`--timeout-seconds` オプションがある。既定値はそれぞれ3回、15秒、120秒。
対話モードは `/exit` または `/quit` で終了できる。
